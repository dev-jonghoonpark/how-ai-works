# how-ai-works

AI가 실제로 어떻게 동작하는지 — 브라우저에서 직접 실험하며 배우는 인터랙티브 교육 자료 모음입니다.

각 주제는 별도의 레포로 관리되며, 모두 GitHub Pages로 배포되어 있어 설치 없이 바로 실험해 볼 수 있습니다.

- **[How SGD Works](https://github.com/dev-jonghoonpark/how-sgd-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-sgd-works/)
  - 확률적 경사 하강법은 어떻게 전부 보지 않고 내려가는가 — **GD와의 차이는 알고리즘이 아니라 기울기를 몇 개로 계산하느냐(B) 하나뿐**이라는 것부터. 미니배치 화살표 100개를 뽑아 평균이 진짜 기울기로 수렴하는 것을 보는 불편 추정량 실험실, GD와 SGD를 같은 지형에서 동시에 달려 B=40에서 두 궤적이 정확히 겹치는 것 확인, 2,000회 추출로 실측해 이론과 3% 이내로 맞추는 **1/√B 법칙**(비복원 보정까지 넣어 B=N에서 오차가 정확히 0), x축을 "스텝"이 아니라 **"계산한 샘플 기울기 수"**로 바꿔 다시 붙는 예산 경주(1에폭 시점 남은 거리가 B=1은 0.023, GD는 6.44), ImageNet 90에폭이 GD에겐 90번·SGD에겐 450,450번의 갱신이 되는 계산기, σ=0이면 탈출률 0%인 지역 최솟값 탈출 측정기, η를 1/4로 줄이면 바닥이 2배 낮아지는 **노이즈 볼**과 Robbins–Monro 조건(Ση=∞, Ση²<∞) — 그리고 체크박스 하나로 **실제 DataLoader의 "에폭마다 셔플"이 교과서의 i.i.d. 추출보다 바닥을 더 낮추는 것**(비율 2 → 3.3)까지 직접 실험하는 인터랙티브 교육 자료
- **[How Adam Works](https://github.com/dev-jonghoonpark/how-adam-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-adam-works/)
  - Adam 옵티마이저는 어떻게 동작하는가 (Kingma & Ba, ICLR 2015) — **파라미터마다 따로 재는 보폭**. 다섯 줄짜리 알고리즘을 한 줄씩 뜯어, β가 곧 "몇 스텝을 기억하는가"(1/(1−β))임을 보는 이동 평균 실험, 편향 보정을 빼면 m보다 v의 편향이 오래 남아 **초반 스텝이 최대 6.57배(t = 12)**로 튀는 배율 곡선(RMSprop의 첫 스텝이 10배인 이유), √v로 나누면 학습률이 "기울기에 곱하는 수"에서 **"한 스텝의 거리"**로 바뀌어 손실 스케일을 ×10 하면 SGD·Momentum은 4~5스텝 만에 발산하지만 Adam 궤적은 그대로인 네 옵티마이저 경주 — 그리고 **Adam이 제일 빠르지는 않고**(Momentum 83스텝 vs Adam 187스텝), 골짜기를 45° 돌리면 축별 보정이 무력해지는 것까지, 노이즈 속에서 스텝/α가 `μ/√(μ²+σ²)`로 줄어드는 자동 담금질(실측 0.710 vs 이론 0.707), 드문 파라미터가 SGD의 1/p 대신 **1/√p**로 배우는 희소 기울기 실험(p = 50에서 2% → 14%), 기울기 크기만 다른 두 가중치가 `Adam(weight_decay)`에서는 **201배** 다르게 줄고 AdamW에서는 정확히 같은 곡선을 그리는 decoupled decay, Adam이 최적해의 정반대(x = +1)로 가고 AMSGrad는 −1로 가는 **Reddi 반례**와 워밍업(RAdam), 7B 학습 메모리 112 GB 중 절반이 m·v라는 계산기까지 직접 실험하는 인터랙티브 교육 자료
- **[How Backprop Works](https://github.com/dev-jonghoonpark/how-backprop-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-backprop-works/)
  - 순전파·손실 함수·역전파 — 필터의 가중치는 어떻게 올바른 값을 찾아가는가. 손실 지형 드래그, 계산 그래프 위에서 한 단계씩 밟아 보는 연쇄 법칙, 실시간으로 사인 곡선을 배우는 신경망, 그리고 난수로 시작한 3×3 합성곱 필터가 손실과 기울기만 보고 소벨 필터로 수렴하는 과정까지 직접 실험하는 인터랙티브 교육 자료
- **[How Convolution Works](https://github.com/dev-jonghoonpark/how-conv-work)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-conv-work/)
  - 합성곱(Convolution)은 실제로 무엇을 하는가 — "뒤집고·밀고·곱하고·더하기" 수학적 정의부터 임펄스 응답(LTI), 확률분포의 합, 합성곱 정리(DFT 검증), 2D 이미지 필터, 채널과 1×1 conv(ResNet bottleneck의 채널 변환), CNN의 스트라이드·패딩까지 직접 실험하는 인터랙티브 교육 자료
- **[How Fourier Transform Works](https://github.com/dev-jonghoonpark/how-fourier-transform-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-fourier-transform-works/)
  - 푸리에 변환(FT)·DFT·FFT — **FFT는 다른 변환이 아니라 DFT를 N log N에 계산하는 알고리즘**이라는 것부터. 복소평면에서 도는 점의 실수부가 사인파가 되는 회전 데모, 사인파 N개로 사각파·삼각파를 쌓으며 보는 1/n vs 1/n² 수렴과 N=60에서도 남는 약 9%의 깁스 현상, 위상이 90° 어긋나면 cos 탐침만으로는 성분이 0으로 보여 e<sup>−i2πft</sup>가 필요해지는 "곱해서 평균 내기", 신호를 원점 둘레에 감아 무게중심을 재는 감기 기계, 수치 적분으로 확인하는 시간 폭×주파수 폭 = 상수(사각 1.207 · 가우시안 0.883), 12 Hz가 8 Hz로 접히는 에일리어싱, 회전 벡터 8개의 합으로 그리는 **8칸 DFT 계산기**, 짝/홀로 쪼개 X[k] = E[k] ± ω<sup>k</sup>·O[k]로 합치는 **FFT 재귀 실행기**(곱셈 64 → 12)와 순진한 DFT 대비 실측 속도, 누설·Hann 창·제로패딩(패딩으로는 못 가르고 N을 늘려야 갈라지는 두 톤), 평균·고역 커널의 주파수 응답으로 확인하는 합성곱 정리 Y = X·H까지 직접 실험하는 인터랙티브 교육 자료

  - 깊은 네트워크는 왜 배치 정규화가 필요한가 — 정규화 개념부터 BN 수식과 γ·β 분포 데모, 역전파에서 γ·β·W가 업데이트되는 플로우 단계별 시각화, ResNet 블록 안에서 BN의 위치, 브라우저에서 직접 계산하는 30층 신호 전파 시뮬레이션(BN·skip 토글), 학습 vs 추론 모드와 BN folding까지 다루는 페이지
- **[ResNet DJL Lab](https://github.com/dev-jonghoonpark/resnet-djl-lab)** · [🔗 데모](https://dev-jonghoonpark.github.io/resnet-djl-lab/)
  - v1과 v2의 차이는 새로운 연산이 아니라 **BN·ReLU·덧셈의 순서** 하나다 — DJL(Deep Java Library) 블록 API로 두 버전을 직접 구현해 파라미터 수를 torchvision·논문 값과 대조하고(ImageNet-18 11,689,512 / CIFAR-20 0.27M 정확히 일치), 잔차 경로의 conv 가중치를 0으로 만들면 출력이 입력과 **비트 단위로** 같아지는 항등 사상을 테스트로 증명한다. 배포된 페이지는 여기서 한 걸음 더 들어가, **고양이 사진 한 장이 순전파 → 손실 → 역전파 → 가중치 갱신 → 재순전파를 한 바퀴 도는 동안 실제로 나온 값**을 80단계 전부 받아 적은 것이다 — 단계마다의 특징 맵·값 범위·0이 된 칸의 비율, conv 출력 한 칸을 만드는 곱셈 27개, BatchNorm의 μ·σ²·γ·β 대입, 평균 풀링 64칸, Linear 내적 64항, `dL/dz = softmax(z) − onehot`, SGD 한 스텝의 `w − lr(g + wd·w)`까지 전부 Java에서 손으로 다시 계산해 엔진 값과 나란히 싣는다(그래디언트 640개를 뺀 나머지는 차이 0). v1/v2 토글로 post-activation과 pre-activation이 같은 이미지에서 어떻게 갈라지는지 볼 수 있다
- **[How Dilated Convolution Works](https://github.com/dev-jonghoonpark/how-dilated-conv-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-dilated-conv-works/)
  - Dilated Convolution은 어떻게 풀링 없이 시야를 넓히는가 (Yu & Koltun, ICLR 2016) — 풀링이 분할 마스크를 뭉개는 과정, 확장률에 따른 커널 읽기 위치, 수용 영역의 지수적 확장(논문 Figure 1 재현), 컨텍스트 모듈(Table 1), 무작위 vs 항등 초기화 신호 전파 비교(ResNet과 같은 "항등 근처에서 시작" 논리), gridding effect까지 직접 실험하는 인터랙티브 교육 자료

  - Karpathy 「The Unreasonable Effectiveness of Recurrent Neural Networks」(2015) 한국어 인터랙티브 해설 — 다섯 가지 시퀀스 처리 방식, step() 한 줄을 손으로 따라가기, 역전파 한 번에 확신도가 오르는 "hello" 실험실(순환 연결을 끊으면 손실이 이론적 하한에 갇힌다), PG·셰익스피어·위키백과·LaTeX·리눅스 다섯 실험의 설정과 실수, 온도 슬라이더, 브라우저에서 학습하는 아기 이름 생성기, 반복 100→4,000 샘플의 진화를 직접 재현하는 셰익스피어 LSTM, 예측 히트맵, 해석 가능한 셀을 상관계수로 찾아내는 셀 탐색기까지 직접 실험하는 인터랙티브 교육 자료
- **[How LSTM Works](https://github.com/dev-jonghoonpark/how-lstm-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-lstm-works/)
  - LSTM은 어떻게 기억하는가 — 야코비안이 반복 곱해지며 생기는 기울기 소멸(λ^k vs f^k 로그 차트), 원소별 곱·덧셈만 지나는 셀 상태 레일, 망각·입력·갱신·출력 4단계 다이어그램, 게이트 조작기(유지·덮어쓰기·지우기·누적), 사람이 직접 심은 가중치로 괄호 깊이를 세는 LSTM 실행기, 핍홀·결합 게이트·GRU 변형과 파라미터 비교(4:3:1), 퀴즈 7문항까지 직접 실험하는 인터랙티브 교육 자료
- **[How GRU Works](https://github.com/dev-jonghoonpark/how-gru-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-gru-works/)
  - GRU는 어떻게 동작하는가 (Cho et al., EMNLP 2014) — **게이트 하나를 덜어 낸 값**. LSTM에서 세 번의 수술(f·i를 `f = 1 − z`로 묶기 → c와 h 합치기 → 리셋 게이트 더하기)로 GRU에 도착하며 가중치가 4벌 → 3벌, **정확히 3/4**가 되는 과정을 보는 수술 단계 뷰어, 새 상태가 이전 상태와 후보를 잇는 **선분 위의 한 점**(볼록 결합)이라는 것을 수직선에서 움직여 보는 한 스텝 계산기, z를 고정하면 이동 평균(오차 0.635)·입력을 보게 하면 샘플 앤 홀드(0.070)가 되고 복사 경로 `∏(1 − z)`가 수십 칸 전 사건까지 줄지 않는 것, 서로 다른 과거 두 개가 경계 이후 **z = 1과 r = 0을 함께 줘야만 정확히 0으로 합류**하는 리셋 게이트 실험(후보가 과거를 업고 들어온다), 상태가 (−1, 1)에 갇혀 **세지 못하는** 대가 — 손으로 심은 카운터에서 LSTM은 n과 무관하게 차이 1, GRU는 `z(2 − qⁿ)qⁿ`으로 흐려져 n = 142에서 float32 한계(Weiss 외 2018), 브라우저가 직접 역전파하는 **RNN·GRU·LSTM 학습 비교**(80칸 전의 한 비트 — RNN은 0.5에 머물고 GRU는 약 140스텝에 풀지만, **게이트 편향을 0으로 두면 GRU·LSTM이 T = 20에서도 실패**), `h_{t−1}`에 걸리는 행렬 곱을 2번 → 1번으로 줄이는 DS2·cuDNN·PyTorch의 **리셋 나중 변형**과 같은 가중치로도 출력이 달라지는 것, z 방향·게이트 쌓는 순서·`b_hn`까지 프레임워크별 차이표를 직접 실험하는 인터랙티브 교육 자료
- **[How RNN Dropout Works](https://github.com/dev-jonghoonpark/how-rnn-dropout-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-rnn-dropout-works/)
  - 드롭아웃은 왜 순환 연결을 피해 가는가 — 논문 「Recurrent Neural Network Regularization」(Zaremba, Sutskever & Vinyals, arXiv:1409.2329 · ICLR 2015 투고). 시간 축으로 펼친 격자에서 세로(비순환)와 가로(순환) 연결 구분, 수식 위 `D(h_t^{l-1})`의 위치, 정보가 손상되는 횟수를 직접 세는 논문 Figure 2·3 재현(**L+1** vs **L+1+Δt**)과 경로 생존 확률 로그 차트, 35스텝을 건너는 유닛 200개의 몬테카를로 생존 시뮬레이션, n=4 미니 LSTM 한 스텝을 실제로 계산하며 보는 게이트 손상, PTB 퍼플렉시티 114.5→78.4와 음성·번역 결과, Gal & Ghahramani·Zoneout의 마스크 샘플링 비교와 PyTorch 구현 주의점까지 직접 실험하는 인터랙티브 교육 자료
- **[How Bidirectional RNN Works](https://github.com/dev-jonghoonpark/how-bidirectional-rnn-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-bidirectional-rnn-works/)
  - 양방향 RNN은 어떻게 동작하는가 — **미래를 보는 대가**. `bidirectional=True` 한 글자가 정확도를 올리는 대신 모델을 실시간에서 추방하는 과정을 축으로, 프레임이 한 칸씩 도착하는 동안 세 구조가 언제 출력할 수 있는지 보는 시간 전개 재생기(양방향은 입력이 끝난 뒤에야 역방향이 오른쪽에서 왼쪽으로 쓸고 내려오고, 출력도 거꾸로 확정돼 **첫 글자가 맨 마지막**에 나온다), 단방향=하삼각·양방향=꽉 참·행 합성곱=하삼각+폭 τ의 띠를 칸 클릭으로 확인하는 의존성 행렬, `/t/`와 `/d/`를 가르는 증거가 자음이 아니라 **다음 모음의 VOT**에 있어 **lookahead 3프레임에서 판정이 뒤집히는** 실험(그리고 τ를 늘리는 것이 늘 이득은 아닌 비단조성), 양방향이 정확히 2배가 아님을 보이는 파라미터 계산기(concat 2.87배 ↔ DS2 식 (6)의 sum·W 공유 1.54배), 역방향 상태에 정답이 들어 있어 언어 모델이 성립하지 않는 **라벨 누수**(BERT의 MLM과 causal mask가 같은 문제의 답), **단방향으로 되돌릴 때만 붙는 층인 행 합성곱**의 상수 지연 예산(τ=19 · 40 ms = 760 ms · 파라미터 51,200개, 채널을 섞었다면 ×2,560), `pack_padded_sequence`를 끄면 역방향이 PAD부터 읽는 패딩 오염 시뮬레이터까지 직접 실험하는 인터랙티브 교육 자료

## 음성 인식 (Deep Speech 2)

- **[How Deep Speech 2 Works](https://github.com/dev-jonghoonpark/how-deep-speech-2-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-deep-speech-2-works/)
  - Deep Speech 2는 실제로 어떻게 동작하는가 (Amodei et al., 2015) — 논문 28쪽을 앞에서부터 따라가며 표와 수식이 나올 때마다 그 값을 브라우저에서 직접 계산해 보는 자료. 7초 발화가 순환층 안에서 스텝 350개가 되는 과정을 8단계로 추적하는 **모양 추적기**(스트라이드를 4로 올리면 영어 유니그램의 "토큰당 스텝"이 3.54 → 1.77로 떨어지고 바이그램이 2.82로 되살리는 것, 중국어는 7.61로 여유가 넘치는 것), **브라우저가 FFT를 직접 돌려 만드는 스펙트로그램**과 창 길이의 시간·주파수 해상도 맞교환, 식 (9)의 모든 정렬을 더하는 **CTC 전진 변수 α를 칸칸이 채우는 실행기**(전수 열거와 대조 검증: `cat`/T=7 → 정렬 210개 · `aa`는 blank 때문에 최소 3프레임), 식 7과 식 8이 통계를 재는 범위가 갈리는 이유와 BatchNorm이 **가장 얕은 모델에서는 오히려 해로웠던** 표 1, 첫 에포크 미니배치 구성기로 보는 SortaGrad, `h(t−1)`에 걸리는 **GEMM 3개가 1개로 합쳐지는** GRU 변형과 1억 파라미터에서 바닐라 RNN에 뒤집히는 표 11, 목소리 높이를 비율로 바꿔 보며 **2D 합성곱은 불변이 아니라 국소적으로 강건할 뿐**임을 재는 실험(3% 변화에 위치 그대로는 0.35, 주파수 ±3칸 여유를 주면 0.93), `the cat sat` → `[th, e, ␣, ca, t, ␣, sa, t]` 바이그램 분해기와 표 5, 표 10에 거듭제곱 법칙을 맞춰 목표 WER에 필요한 시간을 역산하기(논문의 "10배당 40%"가 실제로는 구간별 52.8%/38.7%인 것), 논문의 280 MB vs 1.5 GB를 재구성하는 12 GB 메모리 계산기, 11개 테스트셋에서 사람과의 승부, **Batch Dispatch 이산 사건 시뮬레이터**(eager batching이 10 스트림에서 중앙값 45ms를 내고, 배치를 채우려 기다리면 81ms로 나빠지는 것)까지 직접 실험하는 인터랙티브 교육 자료

- **[How Row Convolution Works](https://github.com/dev-jonghoonpark/how-row-convolution-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-row-convolution-works/)
  - 행 합성곱(row convolution)은 어떻게 미래를 엿보는가 (Amodei et al., 2015 · 3.7절) — 양방향 RNN이 "말이 끝나야" 시작하는 문제를 세 구조 실시간 재생으로 비교, `/t/` vs `/d/`의 판별 증거가 늦게 도착해 lookahead를 늘려야 예측이 뒤집히는 과정, 식 (11)을 칸 클릭으로 직접 전개하며 확인하는 채널 비혼합(= depthwise 1D conv), τ·스텝 상수 지연 예산(논문 τ=19 · 40ms → 760ms), 채널을 섞었다면 파라미터가 정확히 d배(2,560배) 늘어 순환 스택 전체보다 커지는 계산, lookahead를 여러 층에 나누면 지연이 누적되는 이유, 근사가 양방향보다 CER이 낮았던 배포 결과까지 직접 실험하는 인터랙티브 교육 자료
- **[How CTC Beam Search Works](https://github.com/dev-jonghoonpark/how-ctc-beam-search-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-ctc-beam-search-works/)
  - 빔 서치는 무엇을 찾고 있는가 — DS2의 디코딩(3.8절·7.3절) — CTC 축약 2단계와 blank가 글자 경계를 만드는 이유, 4,096개 정렬 전수 열거로 드러나는 greedy의 실패(`"ct"` 0.204 vs `"cat"` 0.425), 접두사마다 `p_b`/`p_nb`를 따로 드는 이유와 **프레임 단위 prefix beam search 스텝 실행기**, 빔 폭 1→50의 포화(폭 2부터 정답·20에서 전수 열거와 100% 일치), `Q(y) = log p_ctc + α log p_lm + β·단어수`의 세 항을 α·β 슬라이더로 뒤집어 보는 재순위와 β가 없으면 단어를 빠뜨리는 이유, 배포 가지치기가 논문의 120만 회 → 8,000회 = 150배를 그대로 재현하는 계산기까지 직접 실험하는 인터랙티브 교육 자료
- **[DS2 My Voice](https://github.com/dev-jonghoonpark/ds2-my-voice)** · [🔗 데모](https://dev-jonghoonpark.github.io/ds2-my-voice/) · 💻 내 컴퓨터에서 학습
  - 앞의 자료들로 부품을 봤다면, 이번엔 DS2를 통째로 조립해 실제로 학습시켜 보는 쪽 — PyTorch로 직접 구현한 축소판 DeepSpeech2(Conv2d 2층 + 양방향 GRU 5층 + CTC, 18.5M)를 Zeroth-Korean 51.7시간으로 RTX 3070 한 장에서 1시간 40분 사전학습(CER 0.776 → 0.171)하고, 화면에 뜬 문장을 읽어 녹음한 **내 목소리 7분**으로 파인튜닝한다. 음절 11,172개 대신 초성·중성·종성 67개로 쪼개는 자모 토크나이저, 짧은 발화부터 학습하는 SortaGrad, 처음 몇 epoch 동안 blank만 내보내는 CTC의 초기 현상까지 코드에서 짚는다. 결과는 학습에 쓰지 않은 내 목소리 19문장에서 CER 0.261 → 0.165(**화자 적응**), 대신 다른 화자 457문장은 0.171 → 0.237로 나빠지는 **망각**. 데모 페이지에서 같은 녹음을 두 모델이 어떻게 받아썼는지 틀린 글자 표시와 함께 들으며 비교할 수 있다

  - Order Matters: Sequence to Sequence for Sets (Vinyals, Bengio & Kudlur, ICLR 2016) — **체인 룰은 어떤 순서로 풀어도 같은 확률을 주는데, 왜 순서를 바꾸면 성능이 달라지는가**. 같은 숫자 다섯 개를 순서만 바꿔 넣으면 RNN의 마지막 상태는 달라지고 임베딩 합은 그대로인 실험, 번역 입력 뒤집기 BLEU +5.0·볼록 껍질 각도순 정렬 최대 +10%p(번호만 다시 매기면 정답 출력이 오름차순이 되는 데모), 식 (3)–(7)을 그대로 구현해 메모리를 섞어도 q*<sub>T</sub> 차이가 반올림 오차(~1e-16) 수준인 **Read-Process-Write**의 Process 블록, 포인터 네트워크와 glimpse, 표 1 정렬 실험(P = 0은 Ptr-Net보다 못하고 P ≥ 1이면 역전, N = 15에서는 최고 10%), 출력 순서 실험(PTB 순방향·역방향 86 vs 3단어 뒤집기 96, 파스 트리 깊이 우선 89.5% vs 너비 우선 81.5%)과 n!개 정답 동치류, 결합분포를 전부 나열해 계산한 별 모양 그래피컬 모델의 스텝별 조건부 엔트로피(합은 같고 조건부의 복잡도가 다르다), 그리고 순서를 모델이 고르게 하는 식 (9) — 120가지 순서의 확률을 전부 계산해 max 탐색과 조상 샘플링을 비교하고, 5! 순서를 섞어 줘도 퍼플렉시티 225로 돌아오는 5-gram 실험(표 2)까지 직접 실험하는 인터랙티브 교육 자료

- **[How Neural Turing Machines Work](https://github.com/dev-jonghoonpark/how-ntm-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-ntm-works/)
  - Neural Turing Machine은 어떻게 동작하는가 (Graves, Wayne & Danihelka, 「Neural Turing Machines」, 2014) — LSTM이 은닉 상태에 섞어 두던 기억을 **망 밖의 N × M 행렬**로 꺼내고, 어디를 읽고 쓸지를 정수 주소가 아니라 **모든 칸에 나눠 준 가중치**로 정해 전체를 경사 하강으로 학습할 수 있게 만든 방법을 3절 수식 (1)~(9) 순서대로 따라간다. 기억 칸을 늘리면 3층 LSTM의 파라미터는 제곱으로 느는데 NTM은 그대로인 계산기(복사 과제 **17,162 vs 1,352,969**, 79분의 1), 초점을 정수 사이로 움직이면 읽기 벡터가 끊김 없이 변하고 정수 주소는 계단이 되는 흐릿한 읽기, 덮어쓰기(e = 1)·누적(e = 0)·흐린 쓰기를 눌러 보는 지우기+더하기, 내용(β) → 보간(g) → 순환 이동(s) → 샤프닝(γ)을 한 화면에서 조작하며 논문의 세 가지 모드(내용만 · 내용으로 찾고 한 칸 옆 · 직전 위치에서 한 칸)를 확인하는 그림 2 파이프라인, 논문 예 s = (0.1, 0.8, 0.1)을 40번 반복하면 봉우리가 **0.14**로 무너지고 γ = 2면 **0.96**에서 버티는 번짐 실험과 0.7칸 분수 이동이 샤프닝 때문에 **40스텝에 28칸 대신 36칸** 가는 부작용, 논문의 복사 의사 코드를 컨트롤러 자리에 넣고 메모리 연산은 식 그대로 돌리는 **손으로 배선한 NTM**(시작 표지를 내용 주소로 찾아 돌아가기 — 이상적이면 길이 40도 틀린 비트 0, L > N이면 시작 표지까지 덮어써 출력 전체가 망가지고, 이동이 흐리면(p = 0.8) 96비트 중 27비트가 틀리지만 γ = 3이면 길이 30까지 다시 0), 정수 주소는 기울기 0으로 한 걸음도 못 가고 흐릿한 주소는 내려가지만 **출발점에 따라 골짜기에 멈추기도 하는** 경사 하강 비교, 다섯 과제 결과와 우선순위 정렬에서는 오히려 NTM이 파라미터가 더 많았던 표 1~3, 그리고 내용 주소 = 어텐션이라는 연결과 DNC까지 직접 실험하는 인터랙티브 교육 자료

- **[그림으로 보는 Transformer](https://github.com/dev-jonghoonpark/illustrated-transformer-ko)** · [🔗 데모](https://dev-jonghoonpark.github.io/illustrated-transformer-ko/)
  - Jay Alammar의 [The Illustrated Transformer](https://jalammar.github.io/illustrated-transformer/)의 장 순서를 따라 새로 쓴 한국어 해설(원문 번역은 [nlpinkorean](https://nlpinkorean.github.io/illustrated-transformer/)에 따로 있다) — 그림을 보는 데서 그치지 않고 **그림 속 숫자를 직접 계산해 보는** 쪽. 블랙박스 → 인코더·디코더 → 6층씩으로 여는 상자, 토큰 순서를 섞어도 **FFN은 물론 어텐션 출력도 한 칸도 안 바뀌는**(셀프 어텐션은 순서를 모르는 "토큰 주머니") 실험과 토큰 하나를 빼면 어텐션만 달라지는 것, 마지막 단어 big/small에 따라 `it`의 시선이 trophy ↔ suitcase로 옮겨 가는 그림, 4차원 장난감 모델로 q·k·v → 내적 → ÷√d<sub>k</sub> → softmax → ×v → 합을 한 단계씩 밟는 손계산기와 **같은 값을 행렬 한 번(`softmax(QKᵀ/√d_k)V`)으로 구해 차이 0**을 확인하는 대조, 나누지 않으면 d<sub>k</sub>가 커질수록 softmax가 한 칸에 몰리는 √d<sub>k</sub> 실험, 헤드 두 개가 서로 다른 곳을 보는 멀티헤드 맵과 h를 1…32로 바꿔도 **가중치 합이 4 × 512²로 그대로**인 표, 논문식(번갈아)과 이어 붙이기(sin | cos) 위치 인코딩 히트맵, "나는 학생 이다" → "i am a student"를 한 단계씩 생성하는 디코더, 온도·로짓 조절기, 학습 진행에 따라 교차 엔트로피가 log 6에서 떨어지는 격자, 탐욕 디코딩이 "i am"(0.200)에 머물 때 빔 2가 "we are"(0.315)를 찾는 확률 트리까지 직접 실험하는 인터랙티브 교육 자료
- **[How Transformer Works](https://github.com/dev-jonghoonpark/how-transformer-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-transformer-works/)
  - Transformer는 어떻게 동작하는가 (Vaswani et al., 「Attention Is All You Need」, NeurIPS 2017) — 앞 자료가 어텐션의 **내부**(Q·K·V·멀티헤드)였다면, 이쪽은 **그 부품을 조립한 블록 하나와 그것을 6번 쌓은 모델 전체**다. 제목과 달리 블록의 무게는 어텐션이 아니라 **FFN에 2배**로 있고(그리고 전체의 30%는 임베딩), 학습이 되느냐를 가른 것도 어텐션이 아니라 **잔차와 LayerNorm의 순서**였다는 것을 축으로 논문을 따라간다. 논문 표 1을 그대로 돌려 **셀프 어텐션이 순환보다 싼 조건이 `n < d` 하나뿐**임을 보는 계산기(n=70에서 순환이 7.11배, n=2048에서는 거꾸로 셀프 어텐션이 4배 — 긴 문맥 문제의 뿌리), 토큰화부터 softmax까지 18단계를 따라가며 **h를 1↔16으로 움직여도 총 파라미터가 한 개도 안 바뀌는 것**을 확인하는 shape 추적기, **위치 인코딩 벡터의 길이가 위치와 무관하게 정확히 √(d/2)**(d=512면 **16**)라서 임베딩(≈1)이 그냥 더하면 묻히고 **√d<sub>model</sub>=22.6을 곱해야 22.6:16으로 저울이 맞는** 것을 재 보는 실험, 기준 위치를 옮겨도 모양이 평행이동할 뿐인 **PE 내적 곡선**(= 거리의 함수)과 밑 10000을 10으로 줄이면 먼 위치 구분이 무너지는 것, 인코더·디코더를 가르는 것이 층의 종류가 아니라 **마스크 행렬 한 장**임을 칸 클릭으로 확인하는 뷰어(여기서 BERT와 GPT가 갈린다), 브라우저가 d=64 잔차 스택을 실제로 순전파해 **가지/줄기 비율이 Post-LN은 1.03→1.08로 그대로인데 Pre-LN은 1.03→0.29(N=48에서 0.17)로 떨어지는 것**을 보이는 신호 전파 시뮬레이터(**워밍업 4000스텝이 미적 선택이 아니라 Post-LN을 살리는 필수 장치였던 이유** — 대신 Pre-LN은 스트림이 √N배로 자라 `final_layer_norm`을 하나 더 붙인다), base **63.08M** · big **214.2M**을 재현하고 임베딩 공유를 끄면 3배로 뛰는 파라미터 계산기, 최고 학습률이 정확히 `(d·warmup)^−0.5` = **6.99e−4**임을 보이는 Noam 스케줄 차트(warmup을 4배 늘리면 최고 학습률은 절반), **완벽히 맞혀도 손실이 1.38 nats 아래로 못 내려가는** 레이블 스무딩과 **퍼플렉시티는 좋아지는데(4.92→4.67) BLEU는 나빠지는(25.8→25.3)** 표 3 (D)행, `O(n²)`를 `O(n)`으로 바꾸는 대신 토큰당 12KB를 내주는 **KV 캐시 계산기**(n=1024에서 약 500배 — 오늘날 MQA/GQA·PagedAttention이 깎으려는 바로 그 한 줄), 그리고 표 3 19행 전체를 클릭해 읽는 절제 실험까지 직접 실험하는 인터랙티브 교육 자료
- **[How Positional Encoding Works](https://github.com/dev-jonghoonpark/how-positional-encoding-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-positional-encoding-works/)
  - 위치 인코딩은 왜 sin과 cos를 **함께** 쓰는가 — 위 자료들이 지나가며 다룬 위치 인코딩 한 줄을 따로 떼어 본다. `dog bites man`을 섞어 넣어도 단어마다 받는 어텐션 출력이 **차이 0**으로 그대로인 실험에서 출발해, sin 하나로는 한 주기 안에 같은 값이 두 번 나와 위치가 모호한 것, (sin, cos) 쌍이 12시에서 시작해 시계 방향으로 도는 **시계 바늘**이라는 것(d<sub>model</sub>=16의 시계 8개에서 pos를 돌려도 pos→pos+k의 호 길이는 그대로), “k칸 뒤”가 **pos가 들어 있지 않은 회전 행렬 M<sub>k</sub>**라는 것을 숫자로 곱해 확인(오차 ~1e−15)하고 sin만으로는 (sin ω·pos, sin ω(pos+k))가 직선이 아니라 **타원**을 그려 선형 예측이 불가능한 것(최대 오차 0.78), ‖PE‖가 항상 √(d/2)이고 PE(pos)·PE(pos+k) = Σcos(ω<sub>i</sub>k)라 기준 위치 셋의 내적 곡선이 **정확히 겹치는** 것(sin만 쓰면 갈라진다), 주기 2π ~ 2π·10000의 초침·분침·시침, 그리고 q·k를 직접 돌려 점수에 n − m만 남기는 **RoPE**까지 직접 실험하는 인터랙티브 교육 자료
- **[How BERT Works](https://github.com/dev-jonghoonpark/how-bert-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-bert-works/)
  - BERT는 어떻게 동작하는가 (Devlin et al., 「BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding」, NAACL 2019) — 앞 자료의 마스크 행렬 뷰어에서 **인코더 쪽을 고른 모델**. 논문 스스로 구조는 원래 Transformer와 "거의 동일"하고 BASE는 일부러 GPT와 같은 크기로 맞췄다고 쓰니, 두 모델의 차이는 **어텐션 마스크 한 장**이고 진짜 기여는 **학습 과제**라는 것을 축으로 논문을 따라간다. 논문 그림 3을 칸 클릭으로 재현해 BERT의 `bank` 아래에는 양쪽을 본 은닉 칸이 14개인데 **ELMo는 맨 위 이어 붙이기 전까지 0개**(얕은 결합)인 것, 마스크를 걷어내면 왜 학습이 안 되는지를 세는 **누수 경로 계수기**(자기 자리를 가려도 **L=2부터 경로 n−1개**, 잔차 연결을 켜면 L=1에서도 샌다 — 논문의 "indirectly see itself"), 같은 두 단어 문맥을 왼쪽 두 개 vs 양쪽 한 개씩으로 쓰는 빈칸 맞히기(73.4% vs 87.7%), 최장 일치 WordPiece로 `play ##ing`을 만드는 그림 2 입력 조립기, 80/10/10에서 **멀쩡해 보이는 토큰 중 3.4%가 예측 대상·1.7%가 거짓말**임을 10만 토큰으로 실측하는 마스킹 발생기와 **파인튜닝은 전략에 둔감하고 특징 기반에서만 `[MASK]`-only가 94.0으로 떨어지는** 표 8, IsNext/NotNext 예제 생성기와 NSP(QNLI −3.5)·양방향(SQuAD −10.1)의 효과를 가르는 표 5, BASE **109,482,240** · LARGE **335,141,888**을 재현하고 표 6에서 **같은 66.96M이 헤드 3개냐 12개냐로 MNLI 1.3%p 갈리는** 것을 보이는 파라미터 계산기, 90%를 길이 128로 돌린 스케줄의 3.25배 절약 중 **제곱 항 몫은 1.055배뿐**이고 같은 가정이면 "40 에폭"이 약 13 에폭이 되는 예산 계산기, MNLI **2,304개**·SQuAD 1,536개·SWAG 768개만 새로 배우는 과제별 머리, 시작·끝 소프트맥스와 v2.0의 `s_null`·τ로 "답 없음"을 판정하는 SQuAD 구간 점수기, GLUE 표 1 비교까지 직접 실험하는 인터랙티브 교육 자료

  - GPT는 어떻게 다음 단어를 고르는가 — 3Blue1Brown 딥러닝 5~7장([DL5](https://www.youtube.com/watch?v=g38aoGttLhI) · [DL6](https://www.youtube.com/watch?v=_Z3rXeJahMs) · [DL7](https://www.youtube.com/watch?v=zHQLPJ8-9Qc))을 따라 GPT 한 모델을 입력부터 출력까지. 분포에서 뽑아 이어 붙이는 생성과 온도, 2D 임베딩에서 직접 해 보는 왕 − 남자 + 여자 ≈ 여왕, 로짓과 소프트맥스 계산표, "a fluffy blue creature" 어텐션 맵의 네 가지 헤드(마스킹을 끄면 **미래 토큰을 베끼는 헤드**), 헤드 하나는 두 형용사가 가중치를 나눠 갖고 둘로 나누면 각자 전부를 주는 Δe 비교, 바이어스를 올리면 OR 게이트가 되고 활성화를 끄면 다른 방향을 빼 버리는 **뉴런 네 개짜리 MLP**(Michael Jordan → 농구), 고차원 랜덤 벡터가 저절로 90° 근처에 몰리는 각도 분포와 최악의 쌍을 웰치 한계까지 밀어내는 실험(영상의 "100차원 1만 개를 89°~91°에" 주장도 바로잡음), 그리고 영상과 같은 **175,181,291,520개·행렬 27,938개**를 재현하는 GPT-3 파라미터 계산기(어텐션 ≈ 1/3, MLP ≈ 2/3)까지 직접 실험하는 인터랙티브 교육 자료
- **[How Universal Transformer Works](https://github.com/dev-jonghoonpark/how-universal-transformer-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-universal-transformer-works/)
  - Universal Transformer는 어떻게 동작하는가 (Dehghani et al., 「Universal Transformers」, ICLR 2019) — **층을 쌓지 말고, 같은 층을 T번**. 가중치 하나의 층을 반복하면 모델이 위치가 아니라 **깊이 방향으로 도는 RNN**이 되고, 그 결과 **파라미터와 연산이 분리된다**는 것을 축으로 논문을 따라간다. RNN·Transformer·UT·UT+ACT의 순차 틱과 가중치 묶음을 색으로 비교하는 재생기, 공유만 하면(UT small) 파라미터는 63.08M → **26.30M**인데 토큰당 연산은 88.3 MFLOP **그대로**이고, 층을 넓혀 파라미터를 base에 맞추면(UT base, d = 1024 · 67.28M) 연산이 **정확히 4배 = Transformer big과 동일**해지는 계산기(논문의 "같은 파라미터에서 +0.9 BLEU"가 무엇과 무엇의 비교인지 — base에 정확히 맞추는 d는 979), 공유된 층에게 "지금 몇 번째 반복인가"를 알려 주는 (위치, 단계) 좌표 임베딩의 길이가 `d + 2Σcos((i − t)ω)`로 **i − t에만 의존**해 i = t에서 √(2d) = 32로 솟는 것, 단계마다 거리 2<sup>t−1</sup>을 읽는 누적 패리티로 보는 **고정 깊이의 한계**(N층이면 2<sup>N</sup>번째 위치까지만 확정 — 길이 40 학습 → 400 평가에 6 → 9단계, 부록 B의 튜링 완전성 논증), 부록 C의 **Listing 2를 한 줄씩 옮긴 ACT 실행기**(정지 편향 초기값 1.0이면 모든 위치가 **2단계에서 멈추고**, Listing 2의 보간은 실효 가중치 합이 `1 − Π(1 − w)`라 초기화 직후 출력의 약 20%가 0 벡터 몫 — Graves의 가중 합과 다른 점), 근거 사실 1·2·3개에 숙고 시간 2.3 → 3.1 → 3.8단계, 평균 8.2단계의 ACT가 **고정 8·9단계보다도 좋았던** LAMBADA 표 3, 유인자가 늘수록 격차가 벌어지는 주어–동사 일치와 알고리즘·LTE·bAbI·번역 결과 탐색기까지 직접 실험하는 인터랙티브 교육 자료
- **[Annotated Transformer Modern](https://github.com/dev-jonghoonpark/annotated-transformer-modern)** · 💻 내 컴퓨터에서 학습
  - How Transformer Works가 논문을 브라우저에서 뜯어 봤다면, 이쪽은 코드를 직접 돌려 보는 쪽 — [The Annotated Transformer](https://nlp.seas.harvard.edu/annotated-transformer/)(Rush 2018, Huang 외 2022 개정)를 최신 라이브러리에서 그대로 돌아가게 고쳤다. 원본이 고정한 torch 1.11은 Python 3.10까지만 설치되고, torchtext는 개발이 중단돼 최신 torch에서 import부터 실패한다(`libtorchtext.so` 로드 실패). 모델·학습·시각화 코드와 본문은 원본 그대로 두고 **4곳만** 고쳤다 — torchtext import 3줄을 같은 동작의 대체 모듈로(Multi30k는 HF Hub, `build_vocab_from_iterator`는 torchtext 0.12와 같은 순서), altair 5+에서 깨지는 차트 필드의 콜론 이스케이프, torch 2.6+에서 **두 번째 실행부터** 깨지는 `torch.load("vocab.pt")`에 `weights_only=False`, Colab 설치 주석. torch 2.14 · spacy 3.8 · altair 6 · pandas 3에서 노트북 전체를 실행해(RTX 3070에서 8 epoch 학습 약 13분, 검증 손실 3.90 → 1.44) 출력까지 담았다
- **[Annotated Transformer Step by Step](https://github.com/dev-jonghoonpark/annotated-transformer-step-by-step)** · [🔗 데모](https://dev-jonghoonpark.github.io/annotated-transformer-step-by-step/)
  - 위 노트북을 어디서부터 읽어야 할지 막막할 때 — 원본은 전체 틀(`EncoderDecoder`)부터 보여 주지만, 이쪽은 **어텐션 함수 한 줄(11줄)짜리 빈 파일에서 시작해 부품을 하나씩 더하며 18단계 만에 원본 코드(1,031줄)를 완성**한다. 단계마다 이전 단계와의 diff, 설명, 그 단계 코드를 실제로 돌린 출력·차트를 나란히 보여 주고(←/→로 넘김), 완성된 코드는 원본 정의 45개 중 41개가 글자 그대로다. 디코더에 뒤쪽 토큰만 바꿔 넣어도 앞쪽 출력 차이가 **정확히 0**인 것, 직접 만든 `MultiHeadedAttention`이 PyTorch `nn.MultiheadAttention`과 1e-7 차이로 같은 것, head를 앞으로 빼는 `transpose(1, 2)`부터 W_O가 head 8개를 섞기까지 텐서 모양을 그림으로 따라가는 것, 그리고 원본 복사 과제가 `[0, 1, …, 9]`를 완벽히 따라 쓰지 못하는 이유가 **학습 때 한 번도 입력으로 나온 적 없는 패딩 id 0으로 시작하기 때문**이라는 실험(학습과 같은 분포의 입력은 100개 중 88개를 완벽히 복사)까지 담았다

## 강화학습과 탐색 (AlphaGo)

- **[How AlphaGo Works](https://github.com/dev-jonghoonpark/how-alphago-works)** · [🔗 데모](https://dev-jonghoonpark.github.io/how-alphago-works/)
  - AlphaGo는 어떻게 동작하는가 (Silver et al., Nature 2016) — **분류용으로만 알던 CNN이 머리 하나만 바꿔 형세 판단기가 되는 과정**을 축으로 논문 전체를 따라가는 자료. 체스와 바둑의 b<sup>d</sup>를 비교하고 정책망은 너비를, 가치망은 깊이를 줄인다는 것을 보는 탐색 공간 계산기, 9×9 판에 돌을 놓으면 48장의 특징 평면(활로·따내기·자충·합리성)이 0/1 격자로 칠해지는 채널 뷰어와 8가지 대칭, 13층 CNN의 수용 영역(구석은 27×27로도 판 전체를 못 본다 → 축 평면을 손으로 넣은 이유), 브라우저가 실제로 끝까지 두는 롤아웃과 1/√n 신뢰구간, 128판씩 두며 기대 승률은 오르고 엔트로피는 0으로 떨어지는 REINFORCE 실험실, 같은 몸통(약 388만 파라미터)에 정책 머리 553개 ↔ 가치 머리 93,122개를 갈아 끼우는 **머리 바꾸기**, **±1 라벨만으로 MSE 최소점이 진짜 승률에 수렴하는 이유**("라벨은 미래에서 온다"), 한 판에서 뽑는 국면 수만 바꿔 train 0.02 / test 1.40으로 벌어지는 **기보 암기 재현 실험**(논문의 0.19 / 0.37 → 판당 1국면으로 해결), 정책망 1순위가 틀린 트리를 탐색이 뒤집는 **MCTS 선택·확장·평가·백업 단계 실행기**, 가치망과 롤아웃을 섞는 λ 스윕, 1순위가 같아도 뾰족한 RL 사전확률은 탐색이 되돌아오지 못하는 비교, 스레드가 한 후보로 몰리지 않게 하는 가상 손실, Elo → 승률 계산기(230점 = 79%)까지 직접 실험하는 인터랙티브 교육 자료
